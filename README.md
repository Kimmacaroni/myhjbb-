# 🤖 명예회장봇 (Honorary Chairman Bot)

KD 사우 가족을 위한 디스코드 봇입니다. 매일 아침 식단표를 알려주고, 고속도로
심한 정체 구간을 실시간으로 알려주며, 서버 활동에 따라 경험치 · 레벨 · 칭호를
자동으로 관리합니다.

---

## ✨ 기능

### 🍚 식단 브리핑
매일 새벽 6시(KST), 식단 API에서 오늘의 식단 정보를 받아 지정 채널로
보냅니다. 로그인이나 검색 없이 메시지만 확인하면 됩니다.

올릴 채널은 **디스코드에서 `/식단채널설정` 명령어로 바로 지정**할 수 있습니다.
설정은 저장되므로 봇을 재시작해도 유지되고, `/식단채널해제` 로 언제든 끌 수 있습니다.

### 🚧 교통정보 알림
전국 고속도로 구간별 소통정보를 한국도로공사 Open API로 5분마다 확인해서,
**새로 심한 정체가 시작된 구간만** 지정 채널에 알립니다. 정체가 계속되는
구간은 반복해서 알리지 않고, 정체가 풀리면 기록에서 지워 나중에 다시
정체되면 새 알림으로 잡습니다.

> ⚠️ 이 API는 사고·공사·통제 같은 "돌발상황" 설명이 있는 API가 아니라,
> 도로 구간별 속도·정체도 숫자만 주는 API입니다. 그래서 **"심한 정체"만**
> 감지하고, 사고나 통제 자체는 알 수 없습니다.

알림 채널은 `/교통정보채널설정` 으로 지정하고, `/교통정보채널해제` 로 끌 수
있습니다. `/교통정보` 로 지금 상황을 바로 조회할 수도 있습니다.

> API 키(`HIGHWAY_API_KEY`)가 없으면 이 기능은 조용히 꺼집니다. 발급 방법은
> 아래 설정 가이드를 참고하세요. 5분 간격 폴링이 필요해 **GitHub Actions
> 방식(방법 A)에서는 지원하지 않습니다** — Cloudflare Workers 또는 상시
> 실행에서만 동작합니다.

### 📈 경험치 시스템
| 활동 | 지급량 | 비고 |
|---|---|---|
| 채팅 | 1회당 15~25 XP | 60초 쿨다운 (도배 방지) |
| 통화방 | 1분당 5 XP | 2명 이상일 때만, 자체 음소거 중엔 제외 |

관리자는 명령어로 직접 지급 · 차감할 수도 있습니다.

### 🎚️ 레벨 시스템
누적 경험치로 레벨이 자동 계산됩니다. 레벨 `L` → `L+1`에 필요한 경험치는
`5L² + 50L + 100` 이라, 초반엔 금방 오르고 고레벨일수록 천천히 오릅니다.

레벨이 오르면 축하 메시지와 함께 **칭호가 자동으로 지급**되고,
경험치가 차감되어 레벨이 내려가면 **칭호도 자동으로 회수**됩니다.

### 🏅 칭호 시스템
칭호는 곧 디스코드 역할입니다.

- `/칭호추가` 하면 서버에 역할이 **자동 생성**됩니다 (멤버 목록에 별도 표시)
- `/칭호삭제` 하면 역할도 **함께 삭제**됩니다
- 요구 레벨이 높은 칭호일수록 **역할 목록 상단에 자동 정렬**됩니다
- 기본값은 "최고 등급 칭호 1개만 유지" 이며, `KEEP_ONLY_HIGHEST_TITLE=0` 으로
  획득한 칭호를 모두 유지하도록 바꿀 수 있습니다

## 🧭 세 가지 실행 방식

| | GitHub Actions (`food_bot.py`) | Cloudflare Workers (`cloudflare/`) | 상시 실행 (`bot.py`) |
|---|---|---|---|
| 호스팅 | 필요 없음 | 필요 없음 (서버리스, 무료) | 24시간 켜둘 서버 필요 |
| 🍚 식단 브리핑 | ✅ | ✅ | ✅ |
| 슬래시 명령어 | ❌ | ✅ | ✅ |
| 📈 경험치 수동 지급 · 레벨 · 칭호 자동 지급 | ❌ | ✅ | ✅ |
| 🚧 교통정보 알림(5분 간격) | ❌ | ✅ | ✅ |
| 채팅/통화방 **자동** 경험치 적립 | ❌ | ❌ | ✅ |

채팅/통화방 자동 적립은 디스코드와 상시 연결(Gateway)이 있어야만 감지할 수
있는 정보라, 서버리스 구조(Actions·Cloudflare Workers) 전부 원리상
불가능합니다. 반면 슬래시 명령어는 디스코드가 그때그때 HTTP로 호출해주는
방식도 지원해서, Cloudflare Workers 같은 무료 서버리스로도 충분합니다.
교통정보 알림도 몇 분 간격 폴링이 필요할 뿐 상시 연결까지는 필요 없어서
Cloudflare Workers의 Cron Trigger로 충분합니다 — 다만 GitHub Actions는
하루 한 번 실행되는 구조라 이 용도로는 쓰지 않습니다.

- **자동 경험치 적립까지 전부 필요 없다면 → Cloudflare Workers** (무료,
  호스팅 관리 불필요). 자세한 설치는 [`cloudflare/README.md`](cloudflare/README.md)
- **호스팅 없이 식단만 필요하다면 → GitHub Actions** (아래 방법 A)
- **채팅/통화방 자동 경험치까지 전부 필요하다면 → 상시 호스팅** (아래 방법 B)

## ⚡ 방법 A — GitHub Actions로 식단만 돌리기

호스팅 없이 바로 쓸 수 있습니다. 저장소에 **Secret 2개만 등록**하면 끝입니다.

`Settings` → `Secrets and variables` → `Actions` → `New repository secret`

| 이름 | 값 |
|---|---|
| `DISCORD_TOKEN` | 봇 토큰 (개발자 포털 → Bot → Reset Token) |
| `MENU_CHANNEL_ID` | 식단을 올릴 채널 ID (채널 우클릭 → ID 복사) |

등록 후 `Actions` 탭 → `Daily Foodpia Bot` → **Run workflow** 로 바로 확인해 보세요.
이후 매일 새벽 6시(KST)에 자동 실행됩니다.

> Actions의 cron은 러너가 붐빌 때 수 분~수십 분 늦게 실행될 수 있습니다.
> 정확한 시각이 중요하면 방법 B를 쓰세요.

식단 조회 실패, 토큰 오류, 권한 부족 등은 **Actions 실행을 실패(빨간색)로 표시**합니다.
조용히 넘어가 며칠 뒤에야 알게 되는 일이 없도록 한 것입니다.

## 🚀 방법 B — 전체 기능 실행하기

### 1. 디스코드 개발자 포털 설정
1. [Developer Portal](https://discord.com/developers/applications) → 해당 앱 → **Bot**
2. **Privileged Gateway Intents** 에서 **SERVER MEMBERS INTENT** 를 켭니다
   (역할 지급과 랭킹 표시에 필요합니다. Message Content Intent는 필요 없습니다.)
3. **Reset Token** 으로 토큰을 발급받습니다

### 2. 봇 초대 권한
`역할 관리(Manage Roles)`, `메시지 보내기`, `링크 첨부` 권한이 필요합니다.

> 초대 URL의 `scope` 에 **`bot` 과 `applications.commands` 가 모두** 들어가야
> 슬래시 명령어가 보입니다. `applications.commands` 가 빠지면 봇은 들어오지만
> `/` 를 눌러도 명령어가 뜨지 않습니다.

> ⚠️ **중요**: 서버 설정 → 역할에서 **봇의 역할을 칭호 역할들보다 위로 올려주세요.**
> 디스코드는 자기보다 위에 있는 역할을 건드리지 못하게 막습니다.

### 3. 설치 및 실행
```bash
pip install -r requirements.txt

cp .env.example .env    # 값을 채운 뒤
export $(grep -v '^#' .env | xargs)
python bot.py
```

> 🚧 **교통정보 알림을 쓰려면** [data.ex.co.kr](https://data.ex.co.kr) 에서
> 무료로 회원가입 후 Open API 인증키를 발급받아 `.env`의 `HIGHWAY_API_KEY`에
> 넣어 주세요. 비워두면 이 기능만 조용히 꺼지고 나머지는 정상 동작합니다.

### 4. 24시간 호스팅
경험치 시스템은 채팅과 통화방을 **실시간으로** 지켜봐야 하므로 봇이 항상 켜져
있어야 합니다. GitHub Actions는 정해진 시각에 잠깐 실행되고 컨테이너가 삭제되는
구조라 이 기능에는 쓸 수 없습니다. 아래 중 하나를 사용하세요.

- **Oracle Cloud 무료 티어** (권장 — 아래에 전용 가이드가 있습니다)
- 라즈베리파이 / 집 PC (`systemd`, `pm2` 등으로 상시 실행)
- AWS Lightsail 등 다른 VPS, Railway·Fly.io 같은 PaaS

어디에 올리든 **`DB_PATH` 가 재시작 후에도 남는 영구 디스크**여야 합니다.
컨테이너 임시 저장소에 두면 재배포할 때마다 경험치가 전부 사라집니다.

## ☁️ Oracle Cloud 무료 티어로 24시간 호스팅하기

카드 등록은 필요하지만 아래 사양은 **Always Free** 라 계속 무료입니다.
`deploy/` 폴더에 설치를 자동화하는 스크립트를 준비해 뒀습니다.

### 1) 계정 생성 & VM 인스턴스 만들기
1. https://www.oracle.com/cloud/free/ 에서 가입합니다 (신용카드 인증 필요, 과금 없음).
2. 콘솔 → **Compute** → **Instances** → **Create instance**
3. **Image**: `Ubuntu 22.04` 선택
4. **Shape**: `VM.Standard.E2.1.Micro` (Always Free, AMD, 1GB RAM) 을 고르세요.
   > `A1.Flex`(ARM, 더 넉넉한 사양)도 Always Free 지만 리전에 따라 재고가
   > 없다는 오류(Out of capacity)가 자주 뜹니다. 이 봇은 가볍기 때문에
   > `E2.1.Micro` 로 충분하며 항상 바로 생성됩니다.
5. **Add SSH keys** 에서 키 페어를 만들고 **개인키(.key 파일)를 반드시 저장**하세요.
   (다시 다운로드할 수 없습니다.)
6. **Create** 클릭 → 몇 분 뒤 인스턴스가 켜지면 **Public IP** 를 확인합니다.

> 이 봇은 디스코드로 **나가는** 연결만 만들고 외부에서 들어오는 요청을 받지
> 않으므로, 방화벽/보안 목록에서 포트를 따로 열 필요가 없습니다.

### 2) 접속 및 설치
로컬 컴퓨터에서:
```bash
chmod 600 다운로드한-키.key
ssh -i 다운로드한-키.key ubuntu@<Public IP>
```

VM 안에서:
```bash
git clone <이 저장소 주소> honorary-bot
cd honorary-bot
bash deploy/install.sh
```

`.env` 가 없다는 안내가 뜨면 그대로 안내를 따라 채우세요:
```bash
nano .env        # DISCORD_TOKEN, MENU_CHANNEL_ID 등 채우기
bash deploy/install.sh   # 다시 실행하면 서비스 등록까지 완료됩니다
```

### 3) 확인
```bash
sudo systemctl status honorary-bot   # active (running) 이면 정상
journalctl -u honorary-bot -f        # 실시간 로그 (Ctrl+C로 빠져나오기)
```
로그에 `슬래시 명령어 18개 동기화 → /경험치, /랭킹, ...` 가 보이면 성공입니다.
디스코드에서 `/`를 쳐서 명령어가 뜨는지 확인하세요.

### 이후 관리
| 상황 | 명령어 |
|---|---|
| 재시작 | `sudo systemctl restart honorary-bot` |
| 끄기 | `sudo systemctl stop honorary-bot` |
| 부팅 시 자동시작 여부 확인 | `sudo systemctl is-enabled honorary-bot` |
| 코드 갱신 | `git pull && ./.venv/bin/pip install -r requirements.txt && sudo systemctl restart honorary-bot` |
| 설정값(.env)만 변경 | `nano .env` 후 `sudo systemctl restart honorary-bot` |

`Restart=on-failure` 로 등록되어 있어 봇이 죽어도(네트워크 끊김, 예외 등)
10초 뒤 자동으로 다시 켜지고, VM이 재부팅돼도 자동으로 시작됩니다.

## ❓ 슬래시 명령어가 안 보이거나 일부만 보일 때

봇을 켜면 로그에 이렇게 찍힙니다. **이 줄이 먼저 확인 포인트**입니다.

```
[사우가족] 슬래시 명령어 18개 동기화 → /경험치, /랭킹, /경험치지급, ...
```

| 로그 | 원인과 해결 |
|---|---|
| `18개 동기화` 가 찍혔는데 안 보임 | 디스코드 앱 캐시입니다. `Ctrl + R` 로 새로고침하세요. |
| `명령어를 등록할 권한이 없습니다` | 초대 URL에 `applications.commands` 스코프가 빠졌습니다. 그 스코프를 포함해 **다시 초대**하세요 (봇을 추방할 필요는 없습니다). |
| `참여 중인 서버가 없어` | 봇이 아직 서버에 들어가 있지 않습니다. |
| 로그 자체가 없음 | 구버전 `food_bot.py` 가 돌고 있는 겁니다. `python bot.py` 로 실행하세요. |

명령어는 참여 중인 서버에 직접 등록되므로 **재시작 즉시 반영**됩니다.
(전역 등록은 디스코드가 최대 1시간에 걸쳐 반영해 일부만 보이는 문제가 있어
사용하지 않습니다.)

## 📁 구조

```
bot.py              상시 실행 진입점 (경험치·레벨·칭호 + 식단 + 교통정보)
config.py           환경변수 기반 설정
db.py               SQLite 영구 저장소
levels.py           경험치 ↔ 레벨 변환 공식
cogs/
  leveling.py       채팅·통화방 경험치, 레벨업 처리, 조회/조정 명령어
  titles.py         칭호 CRUD, 역할 자동 생성·삭제·정렬
  menu.py           식단 조회 및 매일 6시 전송
  traffic.py        고속도로 정체 구간 조회 및 5분 간격 알림

menu_source.py      식단 조회·임베드 생성 (아래 두 실행 방식이 공유)
traffic_source.py   교통정보 조회·임베드 생성
food_bot.py         GitHub Actions 전용 단발 실행 스크립트
.github/workflows/main.yml   매일 6시 Actions 스케줄
```

식단 형식을 바꾸고 싶으면 `menu_source.py` 한 곳만 고치면 양쪽에 함께 반영됩니다.
교통정보도 마찬가지로 `traffic_source.py` 한 곳만 고치면 됩니다 (다만 이 기능은
GitHub Actions 경로에는 없습니다).

`bot.py` 를 상시 실행하면 식단 기능도 함께 처리되므로, 메시지가 두 번 오지 않도록
**둘 중 하나만 켜세요**:
- `bot.py` 로 통합 → `.github/workflows/main.yml` 의 `schedule` 을 제거하거나 워크플로를 비활성화
- 기존 Actions 유지 → `.env` 에 `ENABLE_MENU_TASK=0`

### 식단 채널은 어떻게 정해지나요?
서버별로 `/식단채널설정` 명령어로 지정한 채널에만 보냅니다. 지정한 적 없는
서버, 또는 `/식단채널해제` 로 끈 서버에는 자동 전송하지 않습니다.

(GitHub Actions 전용 `food_bot.py` 는 명령어/DB가 없는 완전히 별개의 단발
스크립트라, 그쪽만 예외적으로 `MENU_CHANNEL_ID` 환경변수로 채널을 지정합니다 —
"방법 A" 참고.)

## 🔐 보안 주의

이제 모든 스크립트가 토큰을 환경변수에서만 읽습니다. 다만 **예전 커밋 이력에는
토큰이 그대로 남아 있습니다.** 저장소가 공개 상태라면 반드시
**토큰을 재발급(Reset Token)** 하고 새 토큰을 Secret 으로 등록하세요.
재발급하면 유출된 옛 토큰은 즉시 무효가 됩니다.
